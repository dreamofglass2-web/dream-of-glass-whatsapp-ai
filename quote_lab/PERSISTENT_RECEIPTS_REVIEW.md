# יוסי דוד — שמירת קשר בין הודעה להצעת מחיר

סביבת בדיקות בלבד. אין שליחה ללקוחות ואין שינוי במחשבון הפעיל.

לכל הודעה מלאכותית נשמרים החשבון ומספר השולח, הנמען, מזהה ההודעה,
מזהה ההצעה, הגרסה, טביעת המפרט והמחיר המדויק לפני מע״מ.
הקישור נשמר במסד הנתונים ולא תלוי בזיכרון של התהליך.
שמירת הקישור אינה מסמנת שההצעה נמסרה.

| תרחיש | התוצאה המצופה שנבדקת |
| --- | --- |
| פתיחה מחדש או תהליך חדש | הקישור נטען מהמסד ואירוע המסירה מזוהה |
| הודעה כפולה | ההצעה מתעדכנת פעם אחת ורישום האירוע אינו מוכפל |
| קריאה לפני מסירה | נשמרת מסירה; אירוע מאוחר אינו מבטל אישור |
| שינוי מפרט או מחיר | נוצרת גרסה חדשה; אירוע ישן לא מעדכן אותה |
| נמען שגוי או חתימה שגויה | האירוע נדחה ללא עדכון ההצעה |
| ניסיון לשייך מחדש הודעה | הקישור המקורי נשאר קבוע |
| תקלה בין עדכון ההצעה לרישום האירוע | שני העדכונים מתבטלים; אפשר לפתוח מחדש ולנסות שוב |
| כמה הצעות באירוע אחד ואחת אינה תקפה | כל העדכונים באותה פעולה מתבטלים |
| שני תהליכים מטפלים באותה מסירה | נשמר אירוע אחד ללא עדכון כפול |

הבדיקות רצות במסד SQLite מבודד וב־PostgreSQL זמני של GitHub Actions.
ב־SQLite נבדקת גם פתיחה בתהליך חדש. ב־PostgreSQL נבדקים ניתוק חיבור
באמצע עסקה ואירוע מסירה שממתין בזמן שנשמרת גרסת הצעה חדשה.

לאחר מעבר הבדיקות, השלב הבא הוא בניית ממשק ה־CRM עם נתוני דוגמה:
לקוחות, שלבי טיפול, כרטיס לקוח, הצעות ומשימות פנימיות.
חיבור לנתוני לקוחות פעילים או לשליחת הודעות ידרוש אישור מפורש.
